# CLAUDE.md

Guidance for AI coding assistants working in this repository.

## What this project is

MoneyMentor is a **research prototype** for a bounded educational and behavioral-support
system for college students' financial capability. It is not a financial adviser. Read
`docs/RESEARCH_BOUNDARIES.md` before adding any feature that touches student data, AI
behavior, or research procedures.

The developer is learning applied/agentic AI engineering. When introducing a significant
concept, explain it and add an entry to `docs/LEARNING_NOTES.md`. Prefer small, verified
milestones over large generated changes. Ask before starting a new roadmap phase.

## Hard rules

1. **No financial authority.** Never add code that accesses bank accounts, initiates
   payments/transfers/purchases, applies for financial products, or decides for students.
2. **The backend is the policy enforcement point.** Authentication, authorization,
   validation, consent checks, and tool access live in FastAPI. An LLM, n8n workflow, or
   MCP client must never be able to bypass them. User identity comes from the
   authenticated session — never from a client- or model-supplied user ID.
3. **Deterministic safety in code.** Safety and scope checks are application code with
   tests, not prompt instructions alone. Safety rules are never overridden by agent vote.
4. **Fictional data only.** No real student or participant data. Fixtures must be clearly
   labeled (see `apps/web/src/lib/demo-fixtures.ts`).
5. **No research claims from engineering tests.** Evals measure system behavior, not
   student outcomes.
6. **No secrets in code.** Use environment variables; update the `.env.example` files.
7. **No unrequested major dependencies.** Propose them and record the decision.
8. **Verify, then report.** Run checks before claiming something works; report failures.

## Commands

```bash
make setup        # install everything
make api          # FastAPI on :8000 (reload)
make web          # Next.js on :3000
make check        # all lint/type/test/build checks
make migrate      # alembic upgrade head
cd services/api && .venv/bin/alembic revision --autogenerate -m "describe change"
```

## Conventions

**Backend (`services/api`)**
- Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.x (typed `Mapped[...]` models), psycopg 3.
- Settings only via `app/core/config.py` (`get_settings()`); never read `os.environ` elsewhere.
- Dependencies use `Annotated[T, Depends(...)]`.
- Every new model module must be imported in `alembic/env.py` for autogenerate.
- Review every autogenerated migration by hand before applying it.
- Tests: pytest; DB tests are marked `@pytest.mark.integration`.

**Frontend (`apps/web`)**
- Next.js 16 with Cache Components enabled. **Read `apps/web/AGENTS.md`** and the docs in
  `apps/web/node_modules/next/dist/docs/` before writing Next.js code — APIs differ from
  older versions. Uncached data must render inside `<Suspense>`.
- Server-only config has no `NEXT_PUBLIC_` prefix. Never expose secrets to the browser.
- Use design tokens from `src/app/globals.css` (shadcn-compatible names), not raw hex.
- Product naming comes from `src/lib/brand.ts` only.
- Accessibility: semantic landmarks, labeled controls, visible focus, WCAG AA contrast.

## Keep docs current

When behavior changes, update in the same change:
- `docs/ARCHITECTURE.md` — move items from "Proposed" to "Implemented" only when verified.
- `docs/ROADMAP.md` — status of milestones.
- `docs/DECISIONS.md` — any non-obvious technical choice, with alternatives considered.
